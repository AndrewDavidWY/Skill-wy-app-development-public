# 内容、语言、缓存与离线

适用：目录同步、封面、搜索、正文、图片、离线包。证据来源为 E1、E2、E4，见证据索引。

## 单一内容源与兼容演进

官网公开内容生成 Reader v1 静态 JSON，客户端共用数据，不另建一套漂移的 App 正文。层级是 manifest → 七语 catalog → 普通正文/书目录 → 章节；discover、navigation、offline 清单另有各自契约。

- `id` 稳定，跨语言共用；标题、分类展示与顺序不应改变它。
- `content.path` 指向资源，`content.bytes` 和 `sha256` 校验解压后的原始 UTF‑8 JSON 字节。不要先解析重序列化，也不要计算 gzip 传输体。
- `revision` 是内容 hash，不是可排序日期；`date` 保留原发布日期语义，不用构建时间/mtime伪造内容更新时间。
- 章节当前有 SHA‑256，不保证有 bytes 字段。以实有 schema 为准。
- 新增可忽略字段保留旧字段语义；缺少新描述符的旧数据走明确兼容路径，不能宣称做了不存在的 hash 校验。
- 未知内容类型可按产品策略跳过或打开官网；不让单项未知类型摧毁整个目录。

构建端要验证每个公开目录项有有效正文、书有完整公开章节。抽查首篇不能替代资源全量完整性验证。稳定内容修改应沿章节 → 书目录 → catalog → manifest 的 hash 链传播。

## 校验和提交顺序

以下是目标约束，不是所有当前代码均已满足的声明：已检 iOS discover 在写盘前检查代次、取消和语言，catalog 在按请求语言写盘后才检查当前界面语言。修改时须逐路径核对，不能以一处实现代表全部。

1. 下载到候选内存/临时文件，约束路径、源站、响应、大小及 schema。
2. 校验原始字节 hash、身份、请求语言与真实正文语言语义；拒绝重复/无效块结构。
3. 再检查该请求仍是有效代次，没有取消，目标语言仍适用。
4. 在同一串行化所有者内完成“检查归属 → 缓存/状态提交”，避免检查后又被 await 或其他任务切换打断。若磁盘写必须异步，使用版本化候选文件与提交时的再次比较，旧任务不得覆盖当前指针。失败继续展示旧有效内容及来源/时间，不用空列表覆盖。

发布中固定路径可能暂时跨版本：重新获取 manifest/catalog 一次后有限重试；仍不一致就回退，不能无限轮询。客户端刷新不能自动发布缺失的服务器接口。

同语言同请求可合并；语言切换、最后等待者取消和新的请求启动后，旧响应都需要明确归属。尤其测试「新响应先完成，旧响应最后完成」时磁盘缓存仍是新的，而不只看当前画面。

## 封面修复不是补一个 URL

iOS 0.6.10 的缺封面修复确立了以下分支：

- 优先最新已发布的明确封面，不盖掉书籍/编辑选定封面。
- 适用科研文章没有明确封面时，从**对应 revision 的已验证正文**提取首图；旧正文 SVG 链接只允许受约束的文章内来源回退。
- 缓存键包含内容/语言/正文 revision。图 URL 固定时给在线缓存失效机制提供版本，不把 URL 相同当图片未变。
- 「已验证当前正文没有图」是可缓存结果；网络失败不是无图。新修订删除配图后，不能用旧随包映射把它复活。
- App 升级时协调随包快照与磁盘缓存的新旧关系；记录版本依据，不简单永远缓存优先或永远随包优先。
- 异步解析结果落到文章前，再核对该文章仍是同一 revision。控制并发，不为所有列表项同时下载正文。

回归：明确封面、首图、无图、坏 hash、坏身份/语言、非法 URL、并发合并、旧响应、离线重启、删除旧图、新随包快照与较新网络缓存共存。E1 的生产逻辑测试有 16 场景 39 断言。

## 多语言和阅读位置

界面语言不是正文语言。`readingLocale` 驱动正文语言提示、朗读与字体选择。现有默认行为是切全局语言时保留正在阅读的文章和导航，后续目录按新语言载入。若本次请求明确要求同步切换当前正文，则保存旧语言位置，按稳定 ID 获取并校验目标语言正文，分别处理译文缺失、实际正文语言回退及位置无法对应；不能把默认行为当成不可更改的产品要求。

现有 iOS 位置键含 locale 和 article ID，但块 ID 由提取顺序生成。正文插入或重排时，单纯存整数无法证明跨修订精准恢复。后续若做锚点迁移，保留旧键兼容并显式测试找不到锚点的回退；这是待设计能力，不写成已经实现。

## 正文搜索与媒体

离线全文索引要绑定正文 revision。正文比索引新时，保留标题/摘要搜索并说明覆盖范围，不把过期索引标成全量最新。已检 iOS 版本使用随包 search.json；网站在线分片不等于客户端已下载分片。若本次实现在线索引，校验路径、bytes、SHA‑256，并验证先分片后入口的实际上传顺序，避免新入口指向缺失对象。现有网站非 HTML 资源同阶段并发上传，不能声称所有 Reader JSON 已按该顺序原子发布。

图片根据显示尺寸 × 像素密度选择变体，小卡不下载全尺寸。原图和响应式别名要映射到同一资源族；失败时有回退。变体的存在不证明每个客户端都采用它。

博客 `richText` 是服务端可选能力，旧客户端继续读 `blocks`。富文本接入要单独验证链接/锚点往返、表格、图片、字幕及安全降级，不执行任意 HTML/脚本。SVG 可以用经校验的栅格预览；保留原图查看入口。

## 离线边界

- 用户主动选择包；显示实际大小，包完整校验通过后才替换旧包。取消、损坏、超额保留可读旧包。
- W.Y. 当前案例：单包生成上限 32 MiB，iOS 下载包总额 200,000,000 字节。两者不是同一预算，也不是其他 App 通用数值。
- 更新配额要扣除将被替换的旧包再计算；不能双算造成更新失败。
- 包内图片是重新缩放的 JPEG，整个包 hash 保护其字节；不能拿在线原图/预览 hash 比较离线重编码图片。
- 视频、第三方图片、在线音乐、地图等未必随包；说明具体离线范围，不用“已下载”承诺所有媒体可离线。
- 服务端目录移除条目不等于已删除云端旧对象或用户离线副本，撤回策略需要独立决定。
