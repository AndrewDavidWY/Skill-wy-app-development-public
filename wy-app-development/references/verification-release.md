# 验证、安装、发布与归档

## 分层结果，不合并为一个“通过”

| 层 | 要回答的问题 | 不能替代什么 |
| --- | --- | --- |
| 生产逻辑 | 实际状态机/解析/几何代码是否满足边界 | UI、音频、耗电、真机 |
| 数据集成 | schema/hash/路径、缓存竞争、离线替换是否正确 | 已安装客户端接入 |
| UI | 真实视图与导航在指定屏幕/语言/主题是否正确 | 未运行屏幕、系统或真机 |
| 构建签名 | 指定源码能否生成有效目标包 | 安装、启动、商店发布 |
| 设备安装 | 读回版本是否一致，数据是否保持 | 启动及业务交互 |
| 运行与发布 | 真机交互、远端精确提交/资源是否可读 | 其他平台、其他节点 |
| 归档 | 源码/包/报告/补丁是否完整且可恢复 | 清理授权或已删除原件 |

使用 `assets/release-evidence.json`。状态采用 passed / failed / blocked / not_run / not_applicable，并标证据来源。历史报告不写成此次重测。

## 可重复的最小闭环

1. 留下复现步骤与失败证据，记录源码身份、输入、环境、版本。
2. 纯逻辑尽可能编译生产 helper，注入时钟、网络、文件系统或几何夹具。复制算法到测试里会让两份同样错误的代码互证。
3. 覆盖取消、坏数据、旧请求后到、重复点击、后台、关闭再开、深浅色、大字、实际语言与返回状态。
4. 修改共用组件后回归调用方，不只测当前截图。
5. 旧测试失效需核对产品目标，修正定位/准备条件仍保留原断言意图。新启动动画加入后等待首页可操作，不加正式版跳过开关伪造通过。
6. 保留全量失败运行和定向重跑。逐方法说明最终有效结果，不把包含失败的日志文件整体改称通过。

## W.Y. 现有 iOS 纯逻辑检查

在确认的源工程执行，并把报告写到新的 QA 目录：

```sh
python3 tools/test-figure-covers.py --output /new/qa/figure-covers.json
python3 tools/test-discovery-refresh.py
python3 tools/test-profile-scroll.py --output /new/qa/profile-scroll.json
python3 tools/test-startup-sequence.py --output /new/qa/startup.json
python3 tools/test-music-note.py --output /new/qa/music-note.json
```

这些脚本在原工程中，不随 Skill 复制。先确认工具链路径；部分历史 runner 内有旧版本/电脑标签，必须用本次实际输入路径和源码 hash 判断受检对象，不能沿用硬编码 metadata 冒充当前环境。

## 真机覆盖安装

- 检查 toolchain、设备列表与实际当前包；不要写死设备 ID。
- iOS 保持正确 Bundle ID/团队，Android 保持包名/签名关联。不能用卸载重装解决覆盖问题后声称保留数据。
- 只备份必要数据并安全保管；对照收藏、最近、读位、语言、音乐等关键键与离线包。报告总数/一致性，不发布实际阅读明细。
- 安装后读回版本/构建号，再单独启动、再检查行为。手机锁定时，安装可能成功而启动被阻止；记录两种状态，不重复安装。
- 开发签名有效期、目标设备限制与商店版分开。macOS adhoc 预览不等于 Developer ID 签名/公证；Android debug 包不等于商店正式发布。

## 服务端与统计

客户端内置导航存在，不证明远端导航接口上线。确认受检 commit、站点节点、manifest、资源 bytes/hash 和真实 HTTP 读取；分片先上线，再切 manifest。构建结果、PR、合并、CI、OSS 上传与公网验证分别记录。

云端 CI 被跳过或未启动应写 skipped / not_run / blocked，不是通过。不要在没有授权时重跑工作流、改计费/权限或借客户端任务发布网站。

统计至少区分：代码接入 → 事件构造 → 请求已发送/HTTP 响应 → 后台入库 → 报表可见。HTTP 204 只是请求层证据。缺失、零值、未接入、延迟、过期分开显示；地区路由需记录实际读取节点和缓存时间，不把装饰图叫实时分析。

## 归档与继续开发

交付包含源码、可安装包（需要时）、变更说明、补丁、测试报告和校验清单。对照相对路径、文件大小、SHA‑256，而非只看目录大小。源码、签名包和测试证据要指向同一最终版本。

写回外盘前比较开发开始时的基线与当前归档，避免覆盖其他任务更新。备份验证与恢复确认后，仍需相应清理授权才处理原副本；“上传 Skill”不授权清理项目。

发布经验包只带归纳后的规则、源文件定位和脱敏结果。密钥、签名材料、账户/设备 ID、偏好原始备份、用户日志、安装包和私有媒体不进入 Git。
