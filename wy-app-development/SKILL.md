# APP 策划与交付

把历史修复转成可执行判断，先找到问题所属层，再做最小闭环。项目事实和历史阈值是参考，不把某次设计或设备结果变成其他项目的硬性要求。

## 先划定 App 侧范围

与网站策划与交付分开：本 Skill 负责客户端的产品流程、原生交互、状态与缓存、设备适配、测试和安装交付；适配网站时消费其公开内容契约，缺失接口与发布问题交给网站侧处理，不以 App 刷新代替网站上线。

策划先明确用户阅读任务、目标平台与输入方式、在线/离线范围、原生阅读与内嵌网页的边界、必须保留的用户数据和本次验收设备。已有产品以真实基线迭代，不把四端同时开发、商店发布或完整重设计设为默认交付。

## 接手时建立四份基线

1. **源码基线**：确认当前电脑、外盘是否挂载、目标版本/构建号、工作树及正在进行的其他改动。W.Y. 部分归档是没有 `.git` 的独立快照；不要把文件夹日期当最新版本。记录受检源码 hash，复制到新工作目录后开发，不覆盖原始归档。
2. **安装基线**：读回实际已安装版本和构建号。下载目录、签名包与真机可能不是同一版本。
3. **内容基线**：记录服务端 manifest/catalog、语言、正文 revision、随包快照、缓存与离线包各自版本。网站新字段存在，不代表已安装客户端支持。
4. **体验与数据基线**：复现当前问题；保留内容 ID、偏好键、收藏、最近、读位、当前筛选和返回路径。收集必要的脱敏前后对照，不把用户数据放入提交。

用 [改动卡](assets/change-card.md) 记录症状、触发条件、证据、影响层与验收范围。不要先重做整页再寻找根因。

## 关键约束

### 内容状态不能绑在 UI 重建上

稳定 `id` 是收藏和目录身份；`revision` 是具体资源字节版本；`locale` 和 `readingLocale` 分别表示请求/界面语言与真实正文语言。标题、译名、排序、封面变化不应重建身份。W.Y. 现有默认行为是保留当前文章版本及位置，界面和后续目录随全局语言变化。若用户明确要求连当前正文一起切换，按该请求设计：先保留原语言读位，找到同一稳定 ID 的目标语言版本，再验证新旧位置的对应或明确回退；不可默默忽略需求，也不能声称整数块号可跨译文精确映射。

正文块序号只是某一修订的顺序，不是跨修订稳定锚点。保留原键能避免无意清空数据，但不能宣称任意正文改版后一定精准续读；需要单独设计位置迁移与回退。

### 更新是有校验的事务

允许「在线成功 → 已验证同语言缓存 → 随包快照」回退。下载失败、取消、坏 schema、hash 不符和迟到响应不得替换有效缓存。把请求代次与当前语言检查放在**磁盘写入和可见状态提交之前**。共享请求要处理最后一个等待者取消与迟到返回。

封面、目录、搜索、正文、离线包各有刷新策略。不得用“目录刷新成功”承诺整个 App 内容实时同步。

### 交互按输入和状态建模

真实拖动、程序滚动、视口重排、惯性、按钮跳转分别处理。返回一次只执行一次，并终止原触摸的点击。WebView 先回网页历史，历史为空才关闭容器。TV 额外说明焦点去向，桌面额外覆盖鼠标、触控板与键盘。

动效与媒体把「可见、前台、减少动态效果、低电量、播放/暂停、会话」作为输入。停止和完成是不可逆终态；迟到回调不能恢复已关闭的视图或音频。

### 体验统一不等于控件照搬

W.Y. 已采用刊物式标题、留白、细分隔线与真实配图，以及共享主题、目录和阅读组件。继续 W.Y. 时先核对当前确认的设计；独立的深色看板是局部例外，不应扩散为全 App 重做。手机、折叠分栏、TV 与桌面保留各自输入方式、空间和系统能力。

### 测试结果按层记录

生产逻辑 → 数据/组件集成 → UI → 真机 → 发布 → 备份，每层单独写通过、失败、未运行、阻塞。纯状态机通过不证明播放器、读屏、帧率或耗电；签名包生成不证明已安装；已安装不证明已启动；HTTP 204 不证明分析后台已入库。

保留最初失败与修正后复测。若旧测试断言过期，说明它与产品错误的区别，再保留原目标修改测试，不删掉失败就宣布通过。

## 完成闭环

- 修改后重新跑受影响逻辑、必要的共享组件回归与各输入返回链路。
- 多语言至少覆盖本次变化涉及的语言，长译文/大字号/深浅色/减少动态效果按风险补验；全七语与全设备结论必须有全覆盖证据。
- 需要安装时沿用正确身份和签名，覆盖安装并对照数据；设备锁定时报告安装和启动的不同结果，不重复安装或卸载清数据。
- 上传前只暂存本任务文件，检查差异和敏感信息。App、网站、GitHub 文档各自发布，遵守本次授权，不把 Skill 调用当成发布许可。
- 用 [交付证据模板](assets/release-evidence.json) 交付版本、改动、测试、设备/上线状态、限制、回退与归档校验。没有执行的步骤明确写未运行。
